# Coding Conventions

> Generated by gsd-codebase-mapper | Focus: quality | Date: 2026-03-24

## Naming Patterns

**Files:**
- Use `snake_case` for all Dart files: `home_screen.dart`, `firebase_service.dart`, `app_colors.dart`
- Screen files: `{feature_name}_screen.dart` (e.g., `login_screen.dart`, `scan_screen.dart`)
- Provider files: `{domain}_providers.dart` or `{domain}_provider.dart`
- Widget files: `{descriptive_name}.dart` (e.g., `recipe_card.dart`, `common_widgets.dart`)
- Barrel files: short name matching the folder (`widgets.dart`, `models.dart`, `theme.dart`)

**Classes:**
- Use `PascalCase`: `RecipeProvider`, `FirebaseService`, `SmartSearchBar`
- Screen classes: `{FeatureName}Screen` (e.g., `HomeScreen`, `LoginScreen`, `ScanScreen`)
- State classes: `_{ScreenName}State` (e.g., `_HomeScreenState`)
- Private helper widgets: underscore prefix `_CategoryCard`, `_NavItem`, `_FavoriteButton`
- Constants classes: `PascalCase` with private constructor (`AppColors._()`, `AppSpacing._()`)
- Abstract final classes for pure constants: `abstract final class PrefKeys` (see `lib/app/constants.dart`)

**Variables & Fields:**
- Use `camelCase` for all variables: `_isLoading`, `_selectedCategory`, `_searchController`
- Private fields: underscore prefix `_recipes`, `_favoriteIds`, `_cachedRecipes`
- Public getters expose private fields: `List<Recipe> get recipes => _recipes;`
- Boolean getters: `isLoading`, `isFavorite`, `isSignedIn`, `isSynced`

**Constants:**
- Static const fields on utility classes: `AppSpacing.md`, `AppColors.primaryOrange`
- String constants on abstract final classes: `PrefKeys.darkMode`, `AppUrls.helpAndFaq`
- Firestore collection names: `FirestoreCollections.recipes` (see `lib/constants/firestore_constants.dart`)

**Enums:**
- `PascalCase` type, `camelCase` values: `VoiceOverlayMode.recipeSearch`, `_VoiceState.listening`

## Code Style

**Formatting:**
- Dart default formatter (dart format) with default line length
- Consistent 2-space indentation (Dart standard)
- Trailing commas on parameter lists and widget trees to enforce multi-line formatting

**Linting:**
- Uses `flutter_lints` package (version 5.0.0) via `analysis_options.yaml`
- Config: `include: package:flutter_lints/flutter.yaml` -- minimal custom overrides
- Located at `analysis_options.yaml` (root)

**Opacity:**
- Use `withValues(alpha: 0.3)` -- NOT `withOpacity(0.3)` (deprecated in Flutter 3.x)
- Enforced throughout: see `lib/shared/widgets/recipe_card.dart` line 89, `lib/app/routes.dart` line 296

## Constructor Patterns

**Widget Constructors:**
- Always use `super.key` syntax (modern Dart):
  ```dart
  const MyWidget({super.key});
  ```
- Private widgets omit `super.key` (no key needed): `const _NavItem({required this.icon, ...});`
- Use `const` constructor wherever possible
- Use named parameters with `required` for non-optional fields
- Default values for optional parameters: `this.readOnly = false`, `this.isLoading = false`

**Service/Provider Constructors:**
- FirebaseService: singleton via factory constructor (`lib/services/firebase_service.dart` line 22-24):
  ```dart
  static final FirebaseService _instance = FirebaseService._internal();
  factory FirebaseService() => _instance;
  FirebaseService._internal();
  ```
- Providers accept optional service injection for testability:
  ```dart
  RecipeProvider({FirebaseService? service})
      : _firebaseService = service ?? FirebaseService();
  ```

**Model Constructors:**
- `const` constructors with all named parameters
- `required` for mandatory fields, optional with defaults for nullable
- Every model has: `const` constructor, `copyWith()`, `fromJson()` (or `fromFirestore()`), `toJson()` (or `toFirestore()`)
- See `lib/models/models.dart` for the canonical pattern

## Import Organization

**Order (observed across all files):**
1. `dart:` SDK imports (`dart:async`, `dart:convert`, `dart:io`)
2. Flutter framework (`package:flutter/material.dart`, `package:flutter/foundation.dart`)
3. Third-party packages (`package:provider/provider.dart`, `package:go_router/go_router.dart`)
4. Project-internal (`package:smartchefai/...` OR relative `../../`)

**Path Style:**
- Screens and widgets use **relative imports**: `../../app/theme/theme.dart`, `../../providers/app_providers.dart`
- Providers and services use **package imports**: `package:smartchefai/models/models.dart`
- Both styles coexist; prefer relative for intra-feature imports, package for cross-feature

**Barrel Exports:**
- `lib/shared/widgets/widgets.dart` -- exports all shared widgets
- `lib/models/models.dart` -- exports all data models (uses `library;` directive)
- `lib/app/theme/theme.dart` -- exports all theme files
- `lib/providers/app_providers.dart` -- re-exports `firebase_providers.dart`, `meal_plan_provider.dart`, `nutrition_provider.dart`
- Import the barrel, not individual files: `import '../../shared/widgets/widgets.dart';`

## Navigation

**GoRouter is the ONLY navigation system. Never use Navigator directly.**

```dart
// Tab navigation (replaces stack):
context.go('/search');

// Push detail screens (preserves back button):
context.push('/recipe/${recipe.id}', extra: recipe);

// Pop (go back):
context.pop();
```

**Passing data:**
- Use `extra:` parameter on `context.push()` / `context.go()`
- Receive as: `final recipe = state.extra as Recipe?;`
- Never use `Navigator.pushNamed()` or `arguments:`

**Route names:** defined in `AppRoutes` class (`lib/app/routes.dart` line 450-463) as static const strings

**Navigation extensions:** `lib/app/routes.dart` provides `NavigationExtension` on `BuildContext`:
```dart
context.goToRecipe(recipe);  // pushes /recipe/{id} with extra
context.goToSearch(query: 'chicken');
```

## State Management

**Provider pattern with ChangeNotifier:**
- All providers extend `ChangeNotifier`
- Registered in `lib/main.dart` via `MultiProvider` with `ChangeNotifierProvider`
- Five providers: `RecipeProvider`, `UserProvider`, `GroceryListProvider`, `MealPlanProvider`, `NutritionProvider`

**Reading state:**
```dart
// One-time read (event handlers, initState callbacks):
context.read<RecipeProvider>().loadRecipes();

// Reactive rebuild on change:
final recipes = context.watch<RecipeProvider>().recipes;

// Fine-grained subscription:
final isLoading = context.select<RecipeProvider, bool>((p) => p.isLoading);
```

**Mutation pattern -- always immutable updates:**
```dart
// Toggle checked state on grocery item:
_items[index] = _items[index].copyWith(checked: !_items[index].checked);
notifyListeners();
```

**Provider method pattern (loading/error/notify):**
```dart
Future<void> someMethod() async {
  _isLoading = true;
  _error = null;
  notifyListeners();
  try {
    // ... async work ...
  } catch (e) {
    _error = e.toString();
  } finally {
    _isLoading = false;
    notifyListeners();
  }
}
```

## Error Handling

**Patterns:**
- Providers: catch exceptions, store in `_error` field, expose via `String? get error`, call `notifyListeners()`
- Service layer (`FirebaseService`): catch specific exceptions (`FirebaseAuthException`), map to user-friendly strings
- UI layer: show errors via `ScaffoldMessenger.of(context).showSnackBar(...)` after async operations
- Silent fallbacks: non-critical failures (e.g., Firebase sync, search history) use `catch (_) {}` with no rethrow
- Auth errors: switch on `e.code` to produce readable messages (see `lib/services/firebase_service.dart` line 339-360)

**Mounted check after async:**
```dart
await someAsyncOperation();
if (!mounted) return;
// Safe to use context
```

**Try-finally for loading states:**
```dart
try {
  // ...
} catch (e) {
  _error = e.toString();
  rethrow;  // Only rethrow when caller needs to handle (auth flows)
} finally {
  _isLoading = false;
  notifyListeners();
}
```

## Widget Composition Patterns

**StatelessWidget vs StatefulWidget:**
- Screens that fetch data, have forms, or manage local UI state: `StatefulWidget`
- Reusable display widgets (cards, chips, buttons): `StatelessWidget`
- All shared widgets in `lib/shared/widgets/` are `StatelessWidget`

**Private helper widgets:**
- Extract complex subtrees into private `StatelessWidget` classes (underscore prefix)
- Keep them in the same file as the parent screen
- Example: `_CategoryCard`, `_NavItem`, `_FavoriteButton`, `_MetaChip`

**Build helper methods:**
- Long screens decompose `build()` into `_buildHeader()`, `_buildRecipeGrid()`, etc.
- These are private methods on the State class, not separate widgets
- Pattern: `Widget _buildSectionName(BuildContext context) { ... }`

**initState + addPostFrameCallback pattern:**
```dart
@override
void initState() {
  super.initState();
  WidgetsBinding.instance.addPostFrameCallback((_) {
    context.read<RecipeProvider>().loadRecipes();
  });
}
```

**Dispose pattern -- always clean up controllers:**
```dart
@override
void dispose() {
  _searchController.dispose();
  _tabController.dispose();
  super.dispose();
}
```

## Module Design

**Feature-first organization:**
- Each feature in `lib/features/{name}/` contains its screen file(s)
- One screen per file: `{name}_screen.dart`
- No feature-local models or services -- shared via `lib/models/` and `lib/services/`

**Exports:**
- Barrel files for shared code (`widgets.dart`, `models.dart`, `theme.dart`, `app_providers.dart`)
- No barrel files within feature directories
- `library;` directive used in `models.dart` and `app_providers.dart`

**Constants organization:**
- App-wide pref keys, URLs, metadata: `lib/app/constants.dart`
- Firestore collection/field names: `lib/constants/firestore_constants.dart`
- Layout constants: `AppLayout` class in `lib/constants/firestore_constants.dart`
