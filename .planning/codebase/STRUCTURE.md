## Directory Purposes

**`lib/app/`:**
- Purpose: App-level configuration that is not a feature
- Contains: GoRouter route definitions (`routes.dart`), SharedPreferences key constants (`constants.dart`), theme system (`theme/`)
- Key files: `lib/app/routes.dart` (all navigation routes + auth guard), `lib/app/constants.dart` (PrefKeys, AppUrls, AppMeta)

**`lib/features/`:**
- Purpose: Feature-first screen organization. Each feature gets its own directory.
- Contains: One `*_screen.dart` file per feature directory. Screens are StatefulWidget or StatelessWidget.
- Key files: `lib/features/home/home_screen.dart` (main screen), `lib/features/scan/scan_screen.dart` (AI ingredient detection)

**`lib/models/`:**
- Purpose: All domain data classes in a single barrel file
- Contains: `Recipe`, `Nutrition`, `AppUser`, `GroceryList`, `GroceryItem`, `DetectedIngredient`, `BoundingBox`, `MealPlan`, `NutritionGoals`, `SearchHistory`
- Key files: `lib/models/models.dart` -- this is the only file; import it for any model

**`lib/providers/`:**
- Purpose: ChangeNotifier-based state management
- Contains: Five providers, a barrel export
- Key files: `lib/providers/app_providers.dart` (import this, not individual files), `lib/providers/firebase_providers.dart` (RecipeProvider, UserProvider, GroceryListProvider)

**`lib/services/`:**
- Purpose: All external I/O and platform interaction
- Contains: `FirebaseService` singleton (Firestore, Auth, Storage, Vision API, TheMealDB), `VoiceSearchService` (speech recognition)
- Key files: `lib/services/firebase_service.dart` (984 lines, the central data gateway)

**`lib/shared/widgets/`:**
- Purpose: Reusable UI components shared across multiple features
- Contains: Search bars, recipe cards, chips, navigation bars, app bars, empty states, buttons, overlays
- Key files: `lib/shared/widgets/widgets.dart` (barrel export -- import this)

**`lib/utils/`:**
- Purpose: Pure utility functions with no side effects
- Contains: `IngredientParser` (voice text parsing), `MealClassifier` (keyword-based recipe-to-meal-slot sorting)
- Key files: `lib/utils/ingredient_parser.dart`, `lib/utils/meal_classifier.dart`

**`lib/constants/`:**
- Purpose: Firestore collection names and UI layout constants
- Contains: `FirestoreCollections`, `FirestoreFields`, `AppLayout`
- Key files: `lib/constants/firestore_constants.dart`

**`data/`:**
- Purpose: Static seed data bundled as a Flutter asset
- Contains: `recipes.json` -- the offline recipe fallback loaded via `rootBundle.loadString()`
- Declared in `pubspec.yaml` under `flutter.assets`

**`dart_defines/`:**
- Purpose: Build-time environment variables (API keys)
- Contains: `dev.json.example` (committed template), `dev.json` (gitignored, actual keys)
- Usage: `flutter run --dart-define-from-file=dart_defines/dev.json`

**`functions/`:**
- Purpose: Cloud Functions source (TypeScript). NOT deployed -- requires Blaze plan upgrade.
- Contains: Function source code, kept for future deployment
- Generated: No
- Committed: Yes

## Naming Conventions

**Files:**
- Screens: `{feature_name}_screen.dart` (e.g., `home_screen.dart`, `scan_screen.dart`)
- Providers: `{domain}_provider.dart` or `firebase_providers.dart` (multi-provider file)
- Models: `models.dart` (single barrel file for all models)
- Widgets: `{descriptive_name}_widgets.dart` or `{component_name}.dart` (e.g., `recipe_card.dart`, `common_widgets.dart`)
- Utils: `{purpose}.dart` (e.g., `ingredient_parser.dart`, `meal_classifier.dart`)
- Theme: `app_{aspect}.dart` (e.g., `app_colors.dart`, `app_spacing.dart`)
- Barrel exports: Same name as directory (`widgets.dart`, `theme.dart`, `models.dart`, `app_providers.dart`)

**Directories:**
- Features: `snake_case` matching the feature name (e.g., `recipe_detail/`, `dietary_preferences/`, `meal_plan/`)
- Shared code: Grouped by type (`widgets/`, `services/`, `providers/`, `models/`, `utils/`)

**Classes:**
- Screens: `{FeatureName}Screen` (e.g., `HomeScreen`, `ScanScreen`, `RecipeDetailScreen`)
- Providers: `{Domain}Provider` (e.g., `RecipeProvider`, `MealPlanProvider`)
- Models: `PascalCase` domain name (e.g., `Recipe`, `AppUser`, `GroceryItem`)
- Widgets: `PascalCase` descriptive name (e.g., `SmartSearchBar`, `RecipeCard`, `GradientButton`)
- Services: `{Domain}Service` (e.g., `FirebaseService`, `VoiceSearchService`)
- Constants: `PascalCase` grouping class with static members (e.g., `AppColors`, `PrefKeys`, `FirestoreCollections`)
- Private widgets: Prefixed with underscore, screen-local (e.g., `_CategoryCard`, `_MatchBadge`, `_ScanOption`)

## Import Patterns

**Barrel Exports (always import these, not individual files):**
- Models: `import 'package:smartchefai/models/models.dart';`
- Providers: `import '../../providers/app_providers.dart';` (re-exports `firebase_providers.dart`, `meal_plan_provider.dart`, `nutrition_provider.dart`)
- Widgets: `import '../../shared/widgets/widgets.dart';` (re-exports all widget files)
- Theme: `import '../../app/theme/theme.dart';` (re-exports all theme files including `AppColors`, `AppSpacing`, `AppTypography`, `AppTheme`)

**Import Style:**
- Package imports for cross-package references: `import 'package:smartchefai/models/models.dart';`
- Relative imports within features: `import '../../app/theme/theme.dart';`
- Third-party package imports first, then project imports

**Path Aliases:**
- No path aliases configured. All imports use either `package:smartchefai/` or relative `../../` paths.

## Where to Add New Code

**New Feature Screen:**
1. Create directory: `lib/features/{feature_name}/`
2. Create screen: `lib/features/{feature_name}/{feature_name}_screen.dart`
3. Add route in `lib/app/routes.dart`:
   - Inside `ShellRoute.routes` if it needs the bottom nav bar
   - As a top-level `GoRoute` with `parentNavigatorKey: _rootNavigatorKey` if it is full-screen
4. Import the screen in `lib/app/routes.dart`
5. Add route name to `AppRoutes` class in `lib/app/routes.dart`

**New Provider:**
1. Create file: `lib/providers/{domain}_provider.dart`
2. Extend `ChangeNotifier`, accept `FirebaseService` in constructor with default
3. Add export to `lib/providers/app_providers.dart`
4. Register in `lib/main.dart` inside the `MultiProvider.providers` list

**New Firestore Collection:**
1. Add collection name constant to `lib/constants/firestore_constants.dart` in `FirestoreCollections`
2. Add CRUD methods to `lib/services/firebase_service.dart`
3. Update `firestore.rules` at project root

**New Model:**
1. Add the class to `lib/models/models.dart` (all models live in this single file)
2. Include `const` constructor, named parameters, `copyWith()`, `fromJson()`, `toJson()`

**New Reusable Widget:**
1. Create file in `lib/shared/widgets/{widget_name}.dart`
2. Add export to `lib/shared/widgets/widgets.dart` barrel file

**New Utility:**
1. Create file in `lib/utils/{utility_name}.dart`
2. Use static methods in a class with private constructor (e.g., `class FooHelper { FooHelper._(); static ... }`)

**New Service Method:**
1. Add method to `lib/services/firebase_service.dart` under the appropriate section comment header (e.g., `// ==================== RECIPES ====================`)
2. Create corresponding provider method if state management is needed
