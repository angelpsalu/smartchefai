## Test Structure

**Suite Organization (Dart):**
```dart
// test/services/ingredient_matching_test.dart

import 'package:flutter_test/flutter_test.dart';
import 'package:smartchefai/models/models.dart';

// Standalone copy of the algorithm under test
List<({Recipe recipe, int matchCount})> filterByIngredients(...) { ... }

// Factory helper for test data
Recipe makeRecipe(String id, List<String> ingredients) => Recipe(
  id: id,
  name: 'Test $id',
  ingredients: ingredients,
  steps: const [],
  prepTime: 10,
  cookTime: 10,
  difficulty: 'Easy',
  cuisine: 'Test',
  dietaryTags: const [],
  nutrition: const Nutrition(
    calories: 100, protein: '10g', carbs: '10g', fat: '5g', fiber: '2g',
  ),
  servings: 4,
  imageUrl: '',
);

void main() {
  // Shared test fixtures declared at top of main()
  final chickenRice = makeRecipe('r1', ['500g chicken breast', '2 cups rice', '1 onion']);
  final chickenOnly = makeRecipe('r2', ['600g chicken thighs', '2 garlic cloves']);
  final beef = makeRecipe('r4', ['500g beef mince', '1 onion', '2 tomatoes']);

  group('filterByIngredients', () {
    test('empty ingredient list returns empty', () {
      expect(filterByIngredients([chickenRice], []), isEmpty);
    });

    test('tier 1 — all ingredients present — included', () {
      final results = filterByIngredients([chickenRice, beef], ['chicken', 'rice']);
      expect(results.length, 1);
      expect(results.first.recipe.id, 'r1');
      expect(results.first.matchCount, 2);
    });
    // ... more tests
  });
}
```

**Patterns:**
- `group()` to organize related tests under a named suite
- Descriptive test names with tier/condition info: `'tier 1 — all ingredients present — included'`
- Shared fixtures at top of `main()`, not in `setUp`
- No `setUp` / `tearDown` used (pure function tests, no setup needed)

## Mocking

**Available Mock Packages (dev_dependencies in `pubspec.yaml`):**
- `mockito: ^5.4.4` -- standard Dart mocking
- `build_runner: ^2.4.13` -- code generation for mockito
- `fake_cloud_firestore: ^3.1.0` -- in-memory Firestore fake
- `firebase_auth_mocks: ^0.14.1` -- mock Firebase Auth

**Current Usage:**
- No mock-based tests exist in the Dart test suite yet
- The one existing test (`ingredient_matching_test.dart`) copies the algorithm locally to avoid Firebase dependencies
- Mock packages are configured and ready to use

**Recommended Mocking Pattern (based on provider constructors):**
```dart
// Providers accept optional service injection:
RecipeProvider({FirebaseService? service})

// In tests, inject a mock:
final mockService = MockFirebaseService();
final provider = RecipeProvider(service: mockService);
```

**What to Mock:**
- `FirebaseService` -- all providers accept it via constructor injection
- `SharedPreferences` -- used for local storage in providers
- Network calls (`Dio`) -- for testing `searchRecipes`, `analyzeImage`

**What NOT to Mock:**
- Pure functions (test directly, as `ingredient_matching_test.dart` does)
- Model `fromJson`/`toJson` (test with raw maps)
- `copyWith` (test with assertions on output)

## Recommendations for New Tests

**When adding tests, follow this pattern:**

1. Place test at `test/{layer}/{feature}_test.dart` mirroring `lib/` structure
2. Use `group()` for logical groupings
3. Use factory helpers (like `makeRecipe`) for test data construction
4. For provider tests, inject mock `FirebaseService` via constructor parameter
5. For Firestore tests, use `fake_cloud_firestore` package
6. For auth tests, use `firebase_auth_mocks` package

**Priority order for adding tests:**
1. `FirebaseService` -- mock Dio, fake Firestore, test caching/fallback logic
2. `RecipeProvider` -- inject mock service, test loading/error/search state transitions
3. Model `fromJson` roundtrips -- especially TheMealDB format parsing in `Recipe._parseIngredients`
4. `GroceryListProvider` -- test local/cloud merge logic and immutable item updates
5. Widget tests for `RecipeCard`, `SmartSearchBar` -- high reuse, high regression risk
